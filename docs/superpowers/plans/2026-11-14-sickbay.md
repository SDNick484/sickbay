# Sickbay Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A private, self-hosted kidney stone history tracker for a patient and a caregiver: events filled in over
time, attached portal documents, an import of the portal's record download with suggestions, a timeline and a
printable doctor summary.

**Architecture:** A standalone Flask + SQLite app. `app.py` holds the Flask object, the guards and every route, in one
section per task; route-free logic lives in sibling modules that take a `sqlite3.Connection`. The whole schema is
created by Task 1, so later tasks add modules and routes but do not edit `db.py`. The frontend is native ES modules
with no build step. Identity comes only from a verified Cloudflare Access JWT checked against an allow-list.

**Tech Stack:** Python 3.12, Flask 3, gunicorn, PyJWT (crypto), SQLite (WAL), standard-library `zipfile` and
`xml.etree`, pytest, plain HTML/CSS/JS (ES modules), Alpine + OpenRC installer, GitHub Actions.

**Spec:** `docs/superpowers/specs/2026-11-14-sickbay-design.md` (mockups beside it). Read both; do not edit either to
make code fit.

**Conventions source:** `SDNick484/gift-tracker` (its `CLAUDE.md`, `installer/`, `ops/tracker-backup`,
`tests/conftest.py`, `identity.py`, `.github/workflows/ci.yml`). Copy its patterns; this plan names only where Sickbay
differs. The privacy scan comes from `SDNick484/jigs` (`.github/scripts/privacy_scan.py`, `tests/test_privacy_scan.py`
and the `privacy-scan` job in `.github/workflows/ci.yml`).

## How this plan runs

One task is one issue is one PR. Each task lists **Files** (what it creates and edits), **Append points** (shared files
it adds to), and **Interfaces** with **Consumes** (from earlier tasks) and **Produces** (for later ones). Every task
also touches three append points whatever its file list says: `CLAUDE.md` (its own section), `tests/conftest.py` (its
own fixtures, at the end) and `app.py` (its own routes section). Task 1 creates those sections as headings so each
later task adds lines under its own heading and never edits another's.

## Global Constraints

- Runtime dependencies must exist as Alpine `py3-*` packages: `py3-flask py3-gunicorn py3-jwt py3-cryptography`. Prefer the standard library (no `lxml`, no `defusedxml`).
- No frontend framework, bundler or npm step. Native ES modules in `static/js/`.
- The repository is public and generic: no personal names, dates, providers, hospitals, locations or real records, in files, commits, branch names or PR text. Generic names (Alex, Sam; Dr. Rivera, Dr. Chen), `example.com` emails, RFC 5737 addresses. All test data synthetic. Real portal downloads and credentials never enter the repository.
- Identity only from a verified `Cf-Access-Jwt-Assertion` whose email is in `ALLOWED_EMAILS`. No LAN role, ever. Development exception only with `DEV_EMAIL` set, a loopback address and no Cloudflare header; the installer never writes `DEV_EMAIL`.
- Default deny: every route answers 403 `{"error": "Forbidden"}` without identity, except `/healthz` (`ok`).
- Every non-GET/HEAD `/api/` request needs header `X-Sickbay: 1` and a same-origin `Origin`; a JSON body unless the view is marked `@multipart`.
- Read bodies with `common.json_body()`, strings with `common.text()`, dates with `common.parse_date()`; bad shapes are 400. Never store non-finite numbers. Stone size is integer tenths of a mm.
- `Cache-Control: no-store` on every `/api/` response and every file response. CSP with no inline scripts or styles and `frame-ancestors 'none'`; `nosniff`; `Referrer-Policy: no-referrer`.
- Everything user-typed or imported goes through `esc()` before `innerHTML`. No `style=""`.
- No event detail, doctor, note, file name or condition in any `<title>`, the manifest, a URL segment other than numeric ids, or a log line. Page title and manifest name are `APP_NAME`, default `Logbook`.
- The app records history and gives no advice: no recommendation, risk score or projected date anywhere, in UI text or API.
- Schema changes go through idempotent `migrate()` and bump `SCHEMA_VERSION`. No manual DB step on the host.
- Lists are data, not code: outcome, location, stone type, visit kind, procedure kind and complication kind are rows.
- Commits: Conventional Commits, one logical change each, author `SDNick484 <SDNick484@users.noreply.github.com>`.
- Docs use OpenRC commands and say `vim`.
- Default port `8774`. Gunicorn binds `127.0.0.1` only. Names: service `sickbay`, `/opt/sickbay`, `/var/lib/sickbay`, `/etc/conf.d/sickbay`, `/var/backups/sickbay`.

## Review Focus

1. A hostile or broken download: a ZIP bomb, a member path like `../../x`, a ZIP inside a ZIP, an XML document with a `DOCTYPE` or entity, a truncated XML file. Each is refused or reported per document with a 4xx or a `failed` count; never a 500, never a file written outside `FILES_DIR`. (Task 7, Task 8)
2. The same record downloaded again a month later, rebuilt by the portal with new document ids for unchanged visits but the same `setId`, and new timestamps: no duplicate files, no duplicate suggestions, and a dismissed suggestion stays dismissed. (Task 8)
3. An uploaded HTML or XML file (or one whose name says `.pdf` but whose content is HTML) opened from the event page: it downloads or shows as a sandboxed PDF/image; it never runs as a page on the app's origin. (Task 5)
4. Dates and sizes typed on a phone: `2025-02-30`, `25/02/2025`, an end before the start, a start in the future; size `7`, `7.5`, `7,5`, `0`, `-1`, `NaN`, `1e9`. Each is stored correctly or refused with 400 and a readable message. (Task 1, Task 3, Task 4)
5. An event left open by mistake a year ago, then a new download imported: later visits are proposed as new episodes, not piled onto the old open event. (Task 8)

Schema v1 (all of it; later tasks do not change it):

```sql
CREATE TABLE meta (key TEXT PRIMARY KEY, value TEXT NOT NULL);
CREATE TABLE lists (
  id INTEGER PRIMARY KEY,
  kind TEXT NOT NULL CHECK (kind IN ('outcome','location','stone_type','visit_kind','procedure_kind','complication_kind')),
  slug TEXT, label TEXT NOT NULL, sort_order INTEGER NOT NULL DEFAULT 0, retired INTEGER NOT NULL DEFAULT 0,
  counts_nights INTEGER NOT NULL DEFAULT 0, UNIQUE (kind, label), UNIQUE (kind, slug));
CREATE TABLE doctors (id INTEGER PRIMARY KEY, name TEXT NOT NULL, specialty TEXT, practice TEXT,
  retired INTEGER NOT NULL DEFAULT 0);
CREATE TABLE events (
  id INTEGER PRIMARY KEY, started_on TEXT NOT NULL, resolved_on TEXT, outcome_id INTEGER REFERENCES lists(id),
  created_by TEXT NOT NULL, created_at INTEGER NOT NULL, updated_by TEXT NOT NULL, updated_at INTEGER NOT NULL,
  CHECK (resolved_on IS NULL OR resolved_on >= started_on));
CREATE TABLE stones (
  id INTEGER PRIMARY KEY, event_id INTEGER NOT NULL REFERENCES events(id) ON DELETE CASCADE,
  size_tenths INTEGER CHECK (size_tenths IS NULL OR size_tenths > 0),
  side TEXT NOT NULL DEFAULT 'unknown' CHECK (side IN ('left','right','both','unknown')),
  location_id INTEGER REFERENCES lists(id), type_id INTEGER REFERENCES lists(id),
  type_from_lab INTEGER NOT NULL DEFAULT 0, suggestion_id INTEGER REFERENCES suggestions(id) ON DELETE SET NULL);
CREATE TABLE visits (
  id INTEGER PRIMARY KEY, event_id INTEGER NOT NULL REFERENCES events(id) ON DELETE CASCADE,
  kind_id INTEGER NOT NULL REFERENCES lists(id), from_date TEXT NOT NULL, to_date TEXT,
  suggestion_id INTEGER REFERENCES suggestions(id) ON DELETE SET NULL,
  CHECK (to_date IS NULL OR to_date >= from_date));
CREATE TABLE procedures (
  id INTEGER PRIMARY KEY, event_id INTEGER NOT NULL REFERENCES events(id) ON DELETE CASCADE,
  kind_id INTEGER NOT NULL REFERENCES lists(id), on_date TEXT, doctor_id INTEGER REFERENCES doctors(id),
  note TEXT, suggestion_id INTEGER REFERENCES suggestions(id) ON DELETE SET NULL);
CREATE TABLE complications (
  id INTEGER PRIMARY KEY, event_id INTEGER NOT NULL REFERENCES events(id) ON DELETE CASCADE,
  kind_id INTEGER NOT NULL REFERENCES lists(id), on_date TEXT, note TEXT,
  suggestion_id INTEGER REFERENCES suggestions(id) ON DELETE SET NULL);
CREATE TABLE followups (
  id INTEGER PRIMARY KEY, event_id INTEGER NOT NULL REFERENCES events(id) ON DELETE CASCADE,
  on_date TEXT, what TEXT NOT NULL, doctor_id INTEGER REFERENCES doctors(id), done INTEGER NOT NULL DEFAULT 0,
  suggestion_id INTEGER REFERENCES suggestions(id) ON DELETE SET NULL);
CREATE TABLE event_doctors (
  event_id INTEGER NOT NULL REFERENCES events(id) ON DELETE CASCADE,
  doctor_id INTEGER NOT NULL REFERENCES doctors(id), role TEXT, PRIMARY KEY (event_id, doctor_id));
CREATE TABLE notes (
  id INTEGER PRIMARY KEY, event_id INTEGER NOT NULL REFERENCES events(id) ON DELETE CASCADE,
  author TEXT NOT NULL, created_at INTEGER NOT NULL, updated_at INTEGER NOT NULL, body TEXT NOT NULL);
CREATE TABLE files (
  id INTEGER PRIMARY KEY, storage_id TEXT NOT NULL UNIQUE, name TEXT NOT NULL, mime TEXT NOT NULL,
  size INTEGER NOT NULL, sha256 TEXT NOT NULL UNIQUE, doc_id TEXT UNIQUE, set_id TEXT, version INTEGER,
  origin TEXT NOT NULL CHECK (origin IN ('upload','import')), created_by TEXT NOT NULL, created_at INTEGER NOT NULL);
CREATE TABLE event_files (
  event_id INTEGER NOT NULL REFERENCES events(id) ON DELETE CASCADE,
  file_id INTEGER NOT NULL REFERENCES files(id) ON DELETE CASCADE, PRIMARY KEY (event_id, file_id));
CREATE TABLE deleted_documents (key TEXT PRIMARY KEY, deleted_at INTEGER NOT NULL);
CREATE TABLE imports (
  id INTEGER PRIMARY KEY, created_by TEXT NOT NULL, created_at INTEGER NOT NULL,
  documents INTEGER NOT NULL, new INTEGER NOT NULL, updated INTEGER NOT NULL, same INTEGER NOT NULL,
  skipped_deleted INTEGER NOT NULL, failed INTEGER NOT NULL, suggestions INTEGER NOT NULL);
CREATE TABLE suggestions (
  id INTEGER PRIMARY KEY, key TEXT NOT NULL UNIQUE, file_id INTEGER REFERENCES files(id) ON DELETE SET NULL,
  import_id INTEGER NOT NULL REFERENCES imports(id),
  kind TEXT NOT NULL CHECK (kind IN ('visit','procedure','complication','stone_type','doctor')),
  on_date TEXT, end_date TEXT, payload TEXT NOT NULL,
  state TEXT NOT NULL DEFAULT 'pending' CHECK (state IN ('pending','accepted','dismissed')),
  target_event_id INTEGER REFERENCES events(id) ON DELETE SET NULL,
  event_id INTEGER REFERENCES events(id) ON DELETE SET NULL, decided_by TEXT, decided_at INTEGER);
CREATE INDEX events_started ON events(started_on);
CREATE INDEX suggestions_state ON suggestions(state, on_date);
```
